# 05 DOTS接続と引継ぎ

[English](05-dots-integration.md) | [ホーム](../README.ja.md)

## 公式仕様と未受入の境界

2026-11-09確認の[Tasks and memory公式資料](https://learn.chatgpt.com/docs/dots/tasks-and-memory)では、接続PCや設定済みCodexクラウド環境への作業委譲を説明しています。新作業が受け取るのは選択した文脈で、全会話ではありません。ローカル作業は接続PCの利用可能性に依存します。これは委譲設計の根拠で、Morukuの研究環境が接続済みという証拠ではありません。

未公開のDOTS REST API、作業ID形式、内部メモリ書込APIを作り上げません。対象アカウントの実ツール・設定を受入時に確認。利用者が指定したDOTS／Codexの拡張なので、別エージェント基盤は作りません。

## 最小の依頼

利用者が一つの研究課題と現在のブリーフをDOTSへ渡します。DOTSは以下の作業パケットを作ります。

1. 研究ID、依頼キー、計画版、期待状態版、期限。
2. 目的と合格条件、固定した出典・データハッシュ。
3. 現在の事実、既存候補・結果参照、未解決の問い。
4. コード版、許可作業領域、実行プロファイル、残予算。
5. 成果物、証拠形式、終了条件、返却先。

全文ログではなく短い本文と参照を渡します。初期目安は関連文脈約2,000トークンまでとし、実クライアントで測定・調整。重要な現行要件は明示し、想起は補助扱い。

担当は受領と外部run IDを返します。会話／タスクIDは輸送情報で、実験台帳の代わりにはしません。DOTSの完了報告を受けたら成果を検証し、研究上の成功と自動認定しません。

## 接続の段階

| 段階 | 方式 | 受入 |
|---|---|---|
| M0 | 人が作業パケットを渡し、既存Git／ファイル機能を使う | 限定した一依頼から識別可能な成果と確認済み結果。常駐不要。 |
| M1 | 既存のDOTS→Codex作業委譲 | 実ローカル／クラウド環境、受領文脈、状態取得、中断を確認。 |
| M2 | 任意の非公開連携アダプタ | 現行の依頼・受領規約と主体を確認して再利用。本repoで私的メールボックスを変更しない。 |
| M3 | 任意の研究MCP・完了イベント | 対象限定操作とメタデータのみ。認証、購読終了、重複排除を受入。 |

プロンプトでローカルファイルを示してもクラウドから取得可能にはなりません。GitHub更新だけでDOTSが即座に起きるとも扱いません。

[MCP Events公式資料](https://developers.openai.com/plugins/build/mcp-events)には、dotsを含む対応クライアントへの購読・署名付き通知があります。将来の任意経路であり、アカウントの能力・制約を検証。通知内容は研究／run ID、状態版、証拠参照までとし、秘密情報や出力内の命令を含めません。安定ID、有限購読、期限、検証、重複排除を受入条件とします。Mattermostの有限PoCは経験として使い、研究通知が実装済みとはしません。

## 必要な役割だけ追加する

最初はDOTS＋Codex一つ。計画とレビューは順番に実施。後で明確な不確実性がある場合だけ、予算・証拠アクセス付きの独立レビューを追加します。新しい観測のないAI同士の往復を増やしません。意見差は証拠で解決するか、未解決と残します。

利用者の途中指示はブリーフ・状態版へ反映。影響する作業のみ取消／置換し、無関係な既存証拠は元の計画版とともに維持します。

## 障害と復旧

- 無応答：pending／期限超過を記録し、実タスク状態・接続を確認してから再送。
- PC停止：状態を保存して依存を報告。別ホスト移行や有料クラウド起動を暗黙に行わない。
- 文脈消失：会話記憶でなく最新台帳と証拠から引継ぎを再生成。
- 実行権期限切れ：実プロセス・成果を照合し、取消か新しい試行IDで再開。
- 重複配送：既存ジョブ状態を返す。意図した反復は別replicate ID。
- DOTS停止：必要に応じ委譲先・実験プロセスを別に止め、終了を確認。統括停止だけで全処理停止としない。

Sleep連携は確認済み一般手順に限定し、DOTS内部記憶や評価解答を操作しません。今回、連絡・スケジュール・プラグイン・購読は作成しません。
