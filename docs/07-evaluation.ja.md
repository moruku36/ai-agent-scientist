# 07 評価と研究の妥当性

[English](07-evaluation.md) | [ホーム](../README.ja.md)

## 四つの独立した問い

| 判定 | 問い | 根拠 |
|---|---|---|
| 実行 | 意図したコードが枠内で動いたか | 終了・資源記録、固定コード・入力・環境 |
| 妥当性 | 仮説を公平に検証する測定か | 計画、動く基準、漏えい・交絡確認 |
| 再現性 | 新しい実行でも整合する結果か | 乱数・環境付き反復、可能なら独立担当／隔離評価 |
| 研究貢献 | 意味があり既存研究と区別できるか | 文献比較、効果・不確実性、代替説明、人の評価 |

一つのAI自己採点にまとめません。自動査読は批判点の提案には使えますが、新規性や正しさの認証にはしません。

## 評価を保護する

実装役は開発データと公開したフィードバックを利用可能。最終評価データ、必要に応じ評価コード、参照解、許可ポリシー、資源受領はアクセス・書込権限の外に置きます。評価器は固定成果だけを受け取り、定義済み情報だけ返します。詳細エラーから隠した答えを漏らしません。

初期は人が保護した評価を起動しても構いません。実際の隔離強度を明記し、同じ無制限アカウントの別プロセスを強い境界とは呼びません。実装役がテスト・共通環境・指標ファイルを変更できるなら、独立評価の主張は不可。

正常、誤り、不正／空出力、時間超過、クラッシュ、評価ファイル置換の合成試料を先に検証。欠損・不正を有利な既定点へ変換しません。

## 開発と最終評価

分割・乱数・課題、主要指標・方向、意味のある効果、反復、終了を事前定義。開発結果でのみ調整し、最終評価前に候補・計画を固定。評価結果を設計へ使った後は開発集合へ移し、確認的主張には新しい未使用集合が必要です。

全候補・全実行・除外を残し、勝者とともに失敗・否定的結果も報告。探索中の最高点と、固定して提出した候補を区別。多数試行中の最高値と一回の成功を混同しません。

## 比較と統計

小規模試行案は所有する合成課題12件を開発6件・未使用評価6件に分け、評価条件ごと3反復。探索的であり一般的主張には不足です。実行前に実課題一覧と対応を固定。

A：現行単一ワーカー、B：A＋外部状態・証拠ハーネス、将来C：B＋適応機能一つを比較。モデル・推論、入力、時間・呼出・資源、ツールを揃え、意図した差を明示。可能なら実行順を交互・ランダム化し、負荷や時期の差を抑えます。

課題ごとの対応差、全反復、平均／中央値、ばらつきを報告。標本に合った課題単位の不確実性評価を使い、同一課題の反復を多数の独立課題と数えません。最良一回や有意差だけでなく、実用効果と不安定性を示し、探索的比較は明記。

高速化研究は数値正しさを先に検証し、ウォームアップ、測定負荷、他負荷、キャッシュを分離。誤った高速実装は失敗。MLでは分割、ラベル漏えい、基準の調整努力、同計算量を確認。記憶・証拠研究は所有する正解で判定し、LLMの感想だけを評価器にしません。

## 費用と研究の進展

全時間、実験時間、呼出、取得可能なトークン、機材資源、人の介入、復旧負担を記録。契約利用、追加API料金、ローカル資源見積、未測定を分けます。追加API予算ゼロでも全作業が無料とはしません。

研究進展は解消した不確実性として記録。支持・反証・判断不能、再現効果、新制約、再現失敗を扱います。否定的結果も有用ですが、原稿生成だけでは進展扱いしません。

## 導入条件

証拠追跡、予算・期限強制、重複しない復旧、ローカル試料の再現、全結果の報告を最初の実用条件にします。性能主張はそれらの統合確認に加え、比較実験が必要。自律科学一般の主張にはさらに広い課題と独立レビューを要します。
