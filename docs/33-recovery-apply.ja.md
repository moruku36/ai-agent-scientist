# 33. リカバリ・プレビューの適用

[README](../README.md) · [32 リカバリ・プレビュー](32-recovery-preview.md) · [English](33-recovery-apply.md)

状態: 作成済み・未実行。すべての検査は保留中です。

`apply_reconciliation_preview(receiver, preview, *, now)` は信頼できるプロセス内の呼び出し元による明示的な操作です。不変の `ReconciliationPreview` を既存の `mark_recovery_for_reconciliation` とその受領CASに接続します。新しいストア、レシーバ生成、時計、IO、プロセス、ネットワーク、権限は追加しません。自動実行はされず、人間の意図も認証しません。

## 手順

1. 読み取り前にプレビューの形を検証します。厳密な型、長さ1..1048576のbytes、data のSHA256と一致する小文字sha256、1024文字以内の空でないrequest_id、小文字のrequest_sha256、1以上の整数expected_revisionが必要です。失敗は値を含まない `RecoveryApplyRefused` です。
2. `build_reconciliation_preview` で一度だけ再構築します。None、状態による拒否、または渡されたプレビューとの差異があれば、書き込み前に拒否します。比較は信頼できるビルダーの出力で行い、渡されたバイト列は解析しません。
3. 期待するダイジェスト、リビジョン、注入された `now` で `mark_recovery_for_reconciliation` へ一度だけ委譲します。そこで独自の検査と受領CASが行われます。

## 限界

- 最初のプレビュー読み取り、再構築、mark時の検査、受領CASは別々のスナップショットです。
- 完全一致は、再構築より前に完了したack・観測・状態の変化を検出します。ただし原子的な全スナップショットのフェンスではありません。再構築後の競合するackはmarkを妨げません。CASが保護するのは受領リビジョンだけです。
- 既にマーク済みの要求は拒否され、冪等な成功にはなりません。
- レシーバとストレージのエラーは伝播します。再試行はしません。
- 精算、ディスパッチ、解放、クリーンアップ、予算、権限は変更しません。
