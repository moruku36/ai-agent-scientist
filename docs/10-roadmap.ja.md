# 10 実装計画と設計判断

[English](10-roadmap.md) | [ホーム](../README.ja.md)

## 今回の設計判断

- 名称は `ai-agent-scientist`。英語標準、日本語版を併設。
- 中心は利用者指定の既存DOTS。研究・実装に既存ChatGPT／Codex。
- 既存の流れを拡張し、設計のためだけにeve・別エージェント基盤・APIキーを導入しない。
- 最初は接続受入済み環境1つ、ローカル状態、CPUワーカー1つ。Windows／Macの実選択と空き資源は実行前確認。
- 台帳・評価を先にし、適応探索・チームは後段。今回、新規定期処理・クラウド・GPU実行なし。
- 公開設計と合成例、非公開運用状態、保護した最終評価を分離。

設計判断であり、環境受入や将来の実行許可ではありません。

## 作業単位

| 作業 | 成果 | 受入 |
|---|---|---|
| P0 実環境 | 接続Codex、資源、データ条件、実機能、研究枠を確認 | 無害なファイル／作業引継ぎと証拠返却。重い測定なし |
| P1 記録契約 | 研究・計画・runと仕様依存・検証対象・知識利用資格、原子的更新・ハッシュ・重複・予算 | 正常／不正、古い書込、重複依頼、対象不一致、期限切れを確認 |
| P2 オフライン一周 | 決定論的CPU実験、基準・候補、人が起動する保護検証／評価、範囲付き受領 | 新領域で再現、仕様／依存差替えと偽受領を拒否、失敗と上限。試料にモデルAPI不要 |
| P3 DOTS／Codex連携 | ブリーフ→限定依頼→候補→範囲付き受領→利用可能知識→次判断 | 実文脈と回収、二重再開なし、案の自己採用なし、最終解答の漏洩なし |
| P4 試行研究 | 生ログ／証拠索引付き引継ぎ比較、または利用者が選ぶ狭い問い | 開発・最終分割を固定し、全条件の結果。数値を事前に入れない |
| P5 適応拡張一つ | 候補保存を先行し、必要なら探索・役割変更 | 同予算で単一ワーカーと比較、悪化も保持 |
| P6 遠隔・長時間 | 任意のNUC台帳／MCP／通知、別ワーカー、保存・取消 | 認証、再起動照合、予算、復元、期限、実配送を受入 |
| P7 研究拡大 | 別テーマ、任意の形式検証adapter・GPU・専門レビュー | 分野別の証明仮定／範囲、データ・資源・実許可。上流ライブラリ利用可能とは仮定しない |

## 実装構成案

```text
src/ai_agent_scientist/
  records/       # 研究・計画・候補・run・主張台帳
  admission/     # スコープ・予算・期限・期待版
  runners/       # 受入済み隔離CPUから開始
  evidence/      # ハッシュ・出所・ページ・書き出し
  evaluation/    # 固定した実証指標。保護実行は分離
  verification/  # 仕様依存全体、範囲付き受領、任意adapter
  knowledge/     # 利用資格view。案と検査済み結果を分離
  integration/   # 引継ぎ。MCP／通知は後段
tests/
  contracts/
  integration/
  reproducibility/
```

予定構成で、今回ランタイムは含めません。可能なら標準ライブラリから始め、必要性を確認して固定依存を追加。対応するスキーマ機能を明示的に検証し、例のスキーマをポリシー実装と扱いません。

## 最初の試行

1. [ブリーフ](../templates/research-brief.ja.md)で反証可能な問いを一つ定義。
2. モデルを呼ぶ前に合成課題・基準・指標を固定。
3. 台帳・dry-run受付・証拠受領を実装し、取消・再送を確認。
4. 受入済み環境へDOTSからCodexの小作業を一つ依頼。
5. 候補の制御外で再現・確認。
6. 許可枠内で事前定義した比較だけ実施。
7. 許可がある場合のみ秘匿した報告を公開し、無改善・否定的結果も含める。

## 受入記録と未決事項

提案・実装・実行・独立確認を分けます。単体試験成功はDOTS接続ではなく、作業成功は新規研究の証明ではありません。今回の確認は文書リンク、日英対応、JSON構造・例、状態表現までです。

実装時に、使用PC、空き資源、非公開保存先、評価隔離、実クライアント経路を決めます。研究課題とモデル利用枠もその段階で設定。設計公開を妨げない事項なので、今回早まって判断を求めません。

## 実装契約の具体化

[11 責務と受け渡し](11-harness-boundaries.ja.md)が正本の分担、重複配送、fencing、親子予算、固定schemaを定め、[12 評価と受入](12-protocol-and-acceptance.ja.md)が固定計画・評価受領・SCI-01〜12を定める。旧CPU例の1,800秒では72試行×最大600秒を予約できないため、実manifestと総予算を起動前に整合させる。今回の更新は設計と合成例の検査までで、実行時受入は未実施。

## 改訂の順序と巻戻し

[13](13-verified-discovery.ja.md)はP1〜P3の拡張であり、新しい研究runtimeではありません。保証を利用する前にSCI-01〜12と該当するSCI-13〜20を受入。まず実証／オフライン経路を成立させ、証明器導入・複数チームserviceは後回し。不整合時は新規知識採用／再利用を止め、不変記録を保存して受入済み単一ワーカーへ戻します。自己申告合格へのfallbackや実験予算追加はしません。
